# ATM OOP Starter

Учебный Java 17/JUnit 5 проект. Он намеренно стартует в красном состоянии: методы с маркером `TODO(student)` бросают `UnsupportedOperationException("Student task")`. Это не дефект инфраструктуры, а исполнимый список заданий.

## Запуск

```bash
./gradlew test
./gradlew test --tests practice.atm.MyATMTest
```

После завершения всех учебных методов ожидается `BUILD SUCCESSFUL`.

## Ответственности классов

- `Hardware` — абстракция аппаратной части. Снимок остатков читается через интерфейс, подтверждённый план передаётся одной командой.
- `MyATM` — валидирует запрос, один раз читает снимок, локально строит план и решает, можно ли выполнить commit.
- `WithdrawalPlan` — immutable value object. После создания его значение невозможно изменить через исходные или возвращённые массивы.
- `InMemoryHardware` — наблюдаемый test double. Он хранит состояние и число вызовов, но не содержит алгоритм подбора купюр.

## Рекомендуемый порядок

1. Запусти тесты и сгруппируй падения по классу.
2. Реализуй `WithdrawalPlan.of`, `billCounts` и `totalAmount`.
3. Добейся зелёного `WithdrawalPlanTest`.
4. Реализуй атомарный `InMemoryHardware.giveBills`.
5. Реализуй `MyATM.withdraw`: validation → one snapshot → local plan → verification → commit.
6. Добейся зелёных `MyATMTest` и `EquivalenceClassesTest`.
7. Добавь собственный класс эквивалентности вместо учебного представителя в последнем тесте.

## Перед каждым новым тестом

Заполни строку:

| Измерение | Класс | Представитель | Ожидаемое поведение |
|---|---|---|---|
| валидность amount | положительная сумма, кратная 50 | 650 | подбор или `false`, hardware читается один раз |

Не добавляй второй пример, если он не меняет ожидаемое поведение и не проверяет отдельную границу.
